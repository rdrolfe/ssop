Who holds what

Executor
router · responder · hunt · intel · drill · atomic · ops
Act inside a fixed procedure. No judgement about severity or truth. Reversible by re-running.
Decider
supervisory · analyst (verdict)
Exercise real authority: approve/deny, verdict, escalate. This gates what executors may do — announced with the rule that produced it.
Human only
confirm-to-close · tuning commits · anything dual-control
Reserved by ADR-008. No agent tier reaches it, however senior.

The test for "decider"

  • Does the decision gate someone else's action?
  • Is it reversible without a human?
  • Was it reserved to a human by an ADR?
  • Two yes, one no → decider. Any "reserved" → human, full stop.
One authority table, not two. The tier shown here is read from docs/roles/ and the registry. The room declares nothing of its own — a second copy of the authority model is exactly how the two drift apart, and drift in an authority system is the bug this platform keeps paying for.

Separation of duties

  • No agent adjudicates a case it escalated.
  • No agent commits a proposal it raised.
  • Decider ≠ executor — supervisory decides, responder acts, you confirm.

Still never, at any tier

  • Act on a chat message as if it were an instruction
  • Render raw attacker-controlled alert text inline
  • Let a proposal suppress itself before you commit it

Message classes

event — something happened.
decision — an agent exercised authority, with its envelope.
proposal — wants you, cannot act.
question — asking.
health — the machine on itself.
answer — you. Advisory.
